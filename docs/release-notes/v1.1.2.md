Security and reliability fixes from a code audit.

### Security
- Restoring app settings only switches on the restored app's **own** accessibility services. A modified
  backup can no longer enable another app's accessibility service.
- Data, permissions and settings are only restored into an app signed by the **same developer** as the
  backed-up one, never into a different app that uses the same package name.
- With a backup password, `meta.json` is now **signed** (`meta.sig`). Restores re-read and verify it, and a
  backup whose description was changed is refused. A backup must also belong to the app whose folder
  it is in.
- Folder restores check their target folder, so a modified backup cannot write outside shared storage.
- Clear warning before backing up messages, call logs or Wi-Fi passwords without a password.

### Reliability
- Replacing an app's data is now reversible: the old files are set aside and put back if the swap fails
  (for example when storage is full), instead of risking that both old and new data are lost.

### Build
- GitHub Actions are pinned to exact commits and updated, and the Gradle download is checksum-verified.

**Encrypted backups made with 1.0.0–1.1.1 have no signature** and are refused by default. Make a new backup
after updating. To restore an older encrypted backup, turn on **Settings → Restore backups from older
versions** (restores then show a warning that the backup could not be checked).

Signed with the same key as earlier versions, so it updates the installed app in place.
